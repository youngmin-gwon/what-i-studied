## Learning Contracts 는 안드로이드 시스템을 배우고 이해하는 기준이다

이 하위 지도는 자료 목록이 아니라 학습 과정의 네 결정을 관리한다.

1. [Android는 API catalog보다 boundary 단위로 먼저 배운다](./learn-android-by-boundary-before-api-catalogs.md) - 무엇을 먼저 구조화할지 정한다.
2. [공식 문서, Codelab, sample, talk는 서로 다른 학습 질문에 답한다](./official-docs-codelabs-samples-and-talks-answer-different-learning-questions.md) - 현재 질문에 맞는 자료 유형을 고른다.
3. [Flutter 개발자는 class 이름보다 개념 경계를 대응시켜야 한다](./flutter-developers-should-map-concepts-not-class-names.md) - 기존 지식의 잘못된 일대일 대응을 교정한다.
4. [학습 경로의 끝은 문서 소비가 아니라 프로젝트 결정이어야 한다](./learning-path-should-end-at-project-decisions-not-note-consumption.md) - 학습 종료 조건을 정한다.

### 판단 기준

새 노트는 학습 순서, 자료 선택, 사전 지식 변환, 종료 조건 중 하나의 판단만 소유해야 한다. 특정 API 사용법은 추가하지 않는다.

### 경계

상위 [Android Learning Path](../android-learning-path.md) 는 독자 배경과 문제별 navigation 을 소유하고, 이 지도는 학습 원칙의 역할 차이만 소유한다.
