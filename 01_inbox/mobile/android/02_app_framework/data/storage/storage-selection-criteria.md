## 저장소 선택: 소유권과 공개 목적을 먼저 묻기

상위 문서: [파일 접근 계약](./file-access.md)
배경 지식: [리눅스 파일 시스템](../../../../../linux/filesystems.md)

관련 노트: [Android 저장소는 데이터 수명과 소유권으로 선택한다](persistence-lifetime-selection.md)

Android 파일 저장소를 고를 때 형식보다 데이터의 소유권을 먼저 본다.

사진이라는 확장자를 가졌다는 이유만으로 MediaStore 에 저장하지 않는다.

사용자가 다른 앱에서 봐야 하는지, 앱만 다시 만들면 되는지로 경계를 나눈다.

### 판단 순서

1. 파일을 앱 밖에서 발견하거나 열어야 하는가?
2. 사용자가 파일의 위치를 직접 결정해야 하는가?
3. 앱 삭제 후에도 남아야 하는가?
4. 다시 다운로드하거나 계산할 수 있는가?
5. 접근 대상이 미디어 컬렉션인가 일반 문서인가?

### 결정표

| 질문 | 선택 |
| --- | --- |
| 앱 내부에서만 쓰는가? | 앱 전용 디렉터리 |
| 삭제해도 다시 만들 수 있는가? | `cacheDir` 또는 외부 캐시 |
| 갤러리·다른 앱에서 보여야 하는가? | MediaStore |
| 사용자가 문서나 폴더를 고르는가? | SAF |
| 사용자가 사진·영상을 고르는가? | Photo Picker |
| 값·행 데이터인가? | DataStore 또는 Room |

앱 전용 디렉터리는 소유권이 앱에 있고 앱 삭제와 함께 사라져도 되는 파일에 맞다.

MediaStore 는 시스템이 관리하는 공유 미디어 컬렉션에 결과물을 등록할 때 맞다.

SAF 는 위치 선택권을 사용자에게 주는 문서 import/export 에 맞다.

Photo Picker 는 제한된 시각 미디어 입력에서 권한 범위를 줄이는 선택이다.

### 흔한 오선택

세션 키를 MediaStore 에 저장하면 공개 범위와 수명이 잘못된다.

앱 내부 임시 영상을 공유 저장소에 넣으면 사용자 갤러리를 오염시킬 수 있다.

사용자에게 PDF 저장 위치를 묻지 않고 앱 전용 폴더에 넣으면 export 기대를 깨뜨린다.

사진 한 장을 위해 전체 미디어를 query 하면 필요한 권한보다 접근 범위가 커진다.

큰 파일이라고 자동으로 공유 저장소를 선택하지 않는다.

큰 private 파일은 앱 전용 외부 디렉터리와 스트리밍으로 처리할 수 있다.

반대로 작은 파일이라도 사용자가 계속 소유하고 다른 앱에서 열어야 하면 SAF 가 맞다.

### 현재 프로젝트 기준

프로필 사진 선택은 Photo Picker 를 우선한다.

앱이 생성한 공유 이미지와 영상은 MediaStore 후보로 둔다.

운동 분석 중간 파일과 네트워크 캐시는 앱 전용 파일로 둔다.

누적 이력과 기간 조회가 필요한 데이터는 파일이 아니라 Room 후보로 판단한다.
