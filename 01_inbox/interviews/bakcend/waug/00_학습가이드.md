## 와그 면접 준비 노트

이 폴더는 제출한 `CV_waug_software_engineer_kr.html` 과 면접 키워드(DB, Spring, JPA, Redis, OAuth2, MSA, Kubernetes, MQ, CI/CD·Argo CD, DDD, 테스트 전략)를 중심으로 정리한 노트입니다. 먼저 mental model 을 잡고, 각 기술의 역할과 검증 방법을 연결한 뒤 실제 이력서 경험에 맞춰 답변을 연습합니다.

**가장 먼저 [큰 그림: 예약 흐름](01_큰그림_예약_흐름.md) 을 읽으세요.** 각 주제 문서는 그 mental model 의 한 부분을 더 자세히 설명합니다.

### 문서 순서

1. [이력서 경험·API·인증](02_이력서_경험_API_인증.md) — REST API, 인증·DB 연동 경험, 면접에서 경험을 설명하는 틀
2. [DB·Spring·JPA](03_DB_Spring_JPA.md) — 데이터 정합성, 트랜잭션, ORM 과 조회 성능
3. [Redis 캐시·분산락](04_Redis_캐시_분산락.md) — 이력서의 토큰 세션 저장 경험과 면접 키워드 구분
4. [OAuth2 인증](05_OAuth2_인증.md) — 이력서의 OAuth2 문장을 사실에 맞게 설명하기
5. [MSA·Kubernetes·MQ](06_MSA_Kubernetes_MQ.md) — 서비스 경계, 오케스트레이션, 비동기 메시지 처리
6. [CI/CD·Argo CD](07_CI_CD_Argo_CD.md) — 개발 Jenkins 와 운영 Argo CD 의 배경 및 GitOps 배포 흐름
7. [DDD](08_DDD.md) — 도메인 규칙과 경계 맥락을 모델에 담는 방법
8. [테스트 전략](09_테스트_전략.md) — 위험과 불변조건에 맞춰 테스트 수준을 고르는 방법

### 시간이 부족할 때

- **먼저:** [큰 그림: 예약 흐름](01_큰그림_예약_흐름.md) 의 여섯 질문(요청·규칙·원장·전달·실행·복구)을 예약 예제로 설명합니다.
- **다음:** 1 번 문서에서 이력서의 실제 경험 범위와 프로젝트 요청→API→저장소 흐름을 설명합니다.
- **그다음:** 2 번 문서에서 DB 트랜잭션과 동시 예약 문제를 익힙니다.
- **이후:** 4 번 문서에서 OAuth2 문장을 검증하고, 3 번 문서에서 Redis 토큰 관리와 캐시·분산락의 차이를 정리합니다.
- **마지막:** 6 번 문서의 개발 Jenkins·운영 Argo CD 배경을 설명하고, 5 번 문서에서 MSA·Kubernetes·MQ 핵심을 정리합니다.
- 시간이 되면 7 번 문서로 서비스 경계와 도메인 용어를 정리하고, 8 번 문서에서 그 규칙을 어떤 테스트로 증명할지 연습합니다.
- Kubernetes/MQ 를 직접 운영하지 않았다면 개념 설명과 실무 경험을 분명히 구분합니다.
- 각 주제의 문답은 짧은 답변부터 시작해 꼬리질문 두 단계까지 소리 내어 연습합니다.

### 답변 원칙

- 구현 경험, 옆에서 협업한 범위, 학습한 개념을 구분합니다.
- 답변의 첫 문장에 결론을 말하고, 이유와 트레이드오프를 덧붙입니다.
- 모르는 부분은 범위를 솔직히 밝힌 다음, 어떻게 확인하고 안전하게 적용할지 설명합니다.
- 설계 질문은 요구사항 → 실패 시나리오 → 정합성 보장 위치 → 관측·검증 순서로 답합니다.
