## 와그 면접 준비 노트

이 폴더는 제출한 `CV_waug_software_engineer_kr.html` 과 면접 키워드(DB, Spring, JPA, Redis, OAuth2, MSA, Kubernetes, MQ, CI/CD·Argo CD, DDD, 테스트 전략)를 중심으로 정리한 노트입니다. 먼저 mental model 을 잡고, 각 기술의 역할과 검증 방법을 연결한 뒤 실제 이력서 경험에 맞춰 답변을 연습합니다.

**가장 먼저 [큰 그림: 예약 흐름](01_큰그림_예약_흐름.md) 을 읽으세요.** 각 주제 문서는 그 mental model 의 한 부분을 더 자세히 설명합니다.

### 문서 순서

아래 번호는 파일 이름 앞의 번호와 같습니다.

- **01** [큰 그림: 예약 흐름](01_큰그림_예약_흐름.md) — 요청·규칙·원장·전달·실행·복구의 여섯 질문
- **02** [이력서 경험·API·인증](02_이력서_경험_API_인증.md) — REST API, 인증·DB 연동 경험, 면접에서 경험을 설명하는 틀
- **03** [DB·Spring·JPA](03_DB_Spring_JPA.md) — 데이터 정합성, 격리 수준, 트랜잭션 전파, Kotlin·JPA 함정, 조회 성능
- **04** [Redis 캐시·분산락](04_Redis_캐시_분산락.md) — 토큰·세션 저장 경험, 캐시 전략, Redisson 락, 선착순 재고
- **05** [OAuth2 인증](05_OAuth2_인증.md) — VMMe Pro 인증 서버 구조와 Password Grant 한계, 세션 vs 토큰, JWT·서명 알고리즘
- **06** [MSA·Kubernetes·MQ](06_MSA_Kubernetes_MQ.md) — 서비스 경계, 장애 전파 방지, Saga, graceful shutdown, 비동기 메시지
- **07** [CI/CD·Argo CD](07_CI_CD_Argo_CD.md) — 개발(Jenkins + Docker Compose)과 운영(Argo CD) 배포 흐름
- **08** [DDD](08_DDD.md) — 도메인 규칙과 경계를 모델에 담는 방법, 이력서의 DDD 적용 사례
- **09** [테스트 전략](09_테스트_전략.md) — 레이어별 테스트 기준(도메인 행위 기반·BDD 에 가까움, 얇은 application 은 테스트 안 함, 인프라는 구현 디테일만), TDD·BDD·커버리지 질문
- **10** [이력서 운영·통합·보안 경험](10_이력서_운영_통합_보안.md) — Ansible, 인증서 갱신, Vaultwarden, Oracle/MyBatis·FTP, Docker, API 계약과 운영 질문
- **11** [MongoDB·폴리글랏 저장소](11_MongoDB_폴리글랏_저장소.md) — 여행 상품 다형적 옵션 모델링, 주문 스냅샷, Embedding vs Referencing, ESR 인덱스, RDB 동기화

### 시간이 부족할 때

- **먼저:** 01 의 여섯 질문(요청·규칙·원장·전달·실행·복구)을 예약 예제로 설명합니다.
- **다음:** 02 에서 이력서의 실제 경험 범위와 프로젝트 요청→API→저장소 흐름을 설명합니다.
- **그다음:** 03 에서 격리 수준, 트랜잭션, 동시 예약 문제를 익힙니다.
- **이후:** 05 에서 인증 서버 설명을 연습합니다. 특히 5.1 저장소 구조와 5.2 Password Grant 한계를 읽고, 직접 작성한 클래스를 이름으로 말할 수 있게 합니다. 04 에서는 Redis 토큰 관리와 캐시·분산락의 차이를 정리합니다.
- **마지막:** 07 의 개발 Jenkins·운영 Argo CD 배경을 설명하고, 06 에서 MSA·Kubernetes·MQ 핵심을 정리합니다.
- 시간이 되면 08 로 서비스 경계와 도메인 용어를 정리하고, 09 에서 그 규칙을 어떤 테스트로 증명할지 연습합니다.
- Kubernetes 는 직접 한 범위(Argo CD 설치, Application 등록, 매니페스트 작성)와 개념으로 아는 범위를 구분하고, MQ 는 개념으로 설명합니다.
- 끝으로 10 을 확인합니다. 특히 이력서에 직접 적은 Ansible 개발 VM 구성은 반드시 준비하고, playbook 의 관리 대상·멱등성 검증·비밀값 처리·실패 복구를 설명합니다. 이어서 인증서·Vaultwarden·레거시 연동과 Jenkins/Argo CD 배포 경로를 확인합니다.
- 각 주제의 문답은 짧은 답변부터 시작해 꼬리질문 두 단계까지 소리 내어 연습합니다.

### 답변 원칙

- 구현 경험, 옆에서 협업한 범위, 학습한 개념을 구분합니다.
- 답변의 첫 문장에 결론을 말하고, 이유와 트레이드오프를 덧붙입니다.
- 모르는 부분은 범위를 솔직히 밝힌 다음, 어떻게 확인하고 안전하게 적용할지 설명합니다.
- 설계 질문은 요구사항 → 실패 시나리오 → 정합성 보장 위치 → 관측·검증 순서로 답합니다.
